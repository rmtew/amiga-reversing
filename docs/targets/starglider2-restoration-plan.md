# Starglider 2: original source restoration

Status: normal-media loader entries/bytes verified. Published source batches cover
startup, drawing masks, Paula sample assets, span dispatches, model/variant data,
secondary object updates, names and shared audio/render storage. Complete C/vasm
byte equality is preserved; 131471 bytes remain unclassified and substantial
function/field meaning remains unresolved. Panel-animation images export as
identified assets and projection scales are documented. Remaining static image
resources and central game-record/function contracts are next.
No interim archives.
Scope: the UA/WOW Amiga disk already imported in this repository. Restore readable
original absolute-address assembly, extracted assets and exact raw payloads. No
relocation, C conversion or replacement OS loader is part of this project.

## Connected acceptance steps

1. Verify natural intro return and main entry against extracted bytes; follow any
   additional loads or self-modification actually encountered.
2. Import the recovered image through existing raw-target services. Resolve
   code/data ownership and structural refusals through canonical facts; never
   suppress a guard merely to emit a listing.
3. Restore connected functions, shared fields and table/asset consumers with
   evidence-backed names. Keep unresolved control/data explicitly unknown.
4. Generate canonical original assembly and INCBIN assets, verify complete raw
   payload equality with C and vasm, and package a standalone clean rebuild.
5. Deliver the copyrighted source/assets/raw output privately with README,
   provenance and checksums. Public commits contain only appropriate tooling,
   metadata and evidence descriptions. Do not promise a DOS HUNK or original
   disk reconstruction without separate demonstrated support.

## First source batch

The registered recovered target is `targets/amiga_raw_starglider2_game/`.
Its source descriptor, initial metadata and append-only Manual Action Log are
published; its `binary.bin` and generated listing remain private. To materialize
the target, copy the extractor's `game_copy.bin` to that `binary.bin`. The
original disk import remains registered separately, preserving its history.

The initial structural refusals at source `$3CD8E` and `$3E112` were inline
WORD dispatch tables. At `$3CD3E/$3CD42` and `$3E0C6/$3E0CA`, indexed PC loads
and LEAs select offsets consumed by the jumps at `$3CD8C/$3E110`. Both tables
occupy 32 bytes; the second selector is explicitly masked with 15. This does
not establish validity of arbitrary first-table indices or every record producer.
Canonical layouts plus required data seeds prevent treating the tables as code.

Five code labels and three further layouts name the entry/initialization path,
workspace clearing loop, platform runtime setup, drawing lookup initialization,
platform/entry flags, workspace-base pointer and 200 WORD raster-row offsets.
The Amiga initializer fills the latter with `0,40,...7960`; indexed renderer
consumers use doubled row indices. Flag bit15 selects the Amiga path; bit0
controls fixed workspace setup and whether SuperState is called. Other flag bits
and general startup-environment contracts remain unassessed.

Two renderer defects were exposed and fixed without changing game bytes:
planned access evidence truncated long CIA mask expressions; numeric absolute-W
addresses in the upper signed half needed explicit sign extension for vasm.
The small synthetic regressions and catalogue/extraction suite pass 77 tests.

## Drawing masks and first Paula assets

Four constant tables at runtime `$3DDAE`, `$3DE2E`, `$3DEAE`, `$3DECE`
contain 32 LONG prefix masks, 32 LONG suffix masks, 16 WORD prefix masks and
16 WORD suffix masks. Every value was checked: prefix `all_bits ^
(all_bits >> index)`, suffix `(1 << (bits-1-index))-1`. Startup at `$3E96E`
combines the prefix at the smaller index with the suffix at the larger index.
The Amiga arm writes all 32x32 LONG entries at `$3FFBA` and all 16x16 WORD
entries at `$40FBA`; the alternate platform arm writes only the first 1024 bytes
of the former. Original seed bytes remain preserved, not promoted into meaningful
precomputed values. The 200 row-offset WORDs and the four constants now have
array elements, not merely owner labels.

The routine at `$4DEDC`, now `initialize_paula_sample_channels`, configures four
channels and enables audio DMA. Three retained sample spans are fixed directly
by its address arithmetic and AUDxLEN WORD counts:

| `$5E5F0..$60A14` | 9252 | `paula_initial_channel2_sample.bin` |

Channel 0 starts at volume 24; channels 1 and 2 start at volume zero. This is

## Recovered span dispatches

Native tracing had incorrectly treated the base of `LEA d8(PC,Dn),An` as a
complete address, dropping the index. Small fixtures reproduced both a false
target for an unknown index and a wrong target for a known nonzero index. The
fix retains numeric indices with proper WORD sign extension and transports the
existing WORD-relative-table value into a PC-indexed LEA. Unknown, clobbered,
unsupported and address-domain-only values do not become numeric indices.
Table scanning/enqueueing also stops before a following zero becomes a bogus
handler at the already-consumed table data. This is scoped recovery, not a full
effective-address evaluator or arbitrary-input jump-table proof.

The two jumps at source `$3CD8C` and `$3E110` now each identify the actual 16
table handlers. Both WORD tables render symbolic target-minus-base expressions.
All 16 planar handlers have color-specific labels: their partial-span writes
OR the inside mask into precisely the planes selected by the four color bits,
AND the outside mask into the others, at plane strides `$2000`. They are handler
entry labels, **not independently callable function contracts**: their initial
BPL uses the flags established before dispatch. The interleaved dispatcher is
named separately; its handler color meanings are not promoted by analogy.

This recovers 6582 additional code bytes (88142 total native code bytes), with
some previously inferred data reclassified as code. The union-based unclassified
complement falls by 3110 to 280484 bytes, not by the entire code increase. Both
assemblers again reproduce all 412736 bytes. Twenty evidence-bearing naming and
reference interpretations are accepted through the normal Decision Journal,
bound to a current exact rebuild receipt; the older 36 ordinary catalogue
actions remain unassessed there.

The focused suite passes 93 tests. Three selected existing native regressions
pass; `test_project_source_facts_v2_pc_indexed_absolute_long_dispatch_table_roundtrips`
has a pre-existing exact-line-format assertion failure, independently reproduced
with the unmodified analyzer. It has not been changed or counted as passing.
See [span-dispatch receipt](../../runtime/observations/starglider2-span-dispatch.json).

## Model catalogue and encoded vertices

The constructor at runtime `$4A2A` selects from 104 LONG pointers at `$18974`.
Entries 0 and 1 intentionally point to the same header: there are 103 distinct
headers at `$18B14..$19570`. Their shared 24-byte prefix contains a last vertex
index, face count, coordinate-pool WORD count, four pointers, and auxiliary face
count. Only a nonzero auxiliary count causes the constructor to consume the
additional LONG at +24. The original catalogue has 58 short and 45 extended
headers. Canonical structures preserve that distinction and the pointer alias;
the shared-prefix pointer type does not assert a uniform 28-byte pointee.

The four prefix pointers identify normal face commands, eight-byte vertex
reference records, a coordinate WORD pool, and an optional vertex-variant pointer
table. The routine at `$56BC` masks each vertex coordinate reference with `$7FFF`
and uses it as a byte offset into the coordinate pool; the sign bit selects a
negated transformed result. These encoded references are not literal XYZ values.
The vertex resolver at `$583C` reads three such references and a fourth WORD:
a negative fourth WORD uses the base record, while a nonnegative value may
select an alternate triple from the chosen variant data. The instance's variant
selector at +3 is not bounded by these consumers alone; variant-table lengths
and variant data extents remain unresolved.

For every original model, the coordinate pool ends at its vertex records.
All three coordinate references in every base vertex are even and in that pool.
Every normal/auxiliary face vertex reference is a multiple of eight within its
model's vertex records. Normal face commands encode their vertex count in bits
10..8; auxiliary commands use bits 11..8. Parsing the declared face counts ends
exactly at the next component. Other face flags/material meanings and the visual
identities of the models have not been inferred. Components of distinct original
models do not overlap. This is original-record validation, not a guarantee for
arbitrary replacement data or all runtime selectors.

## Conditional variant bounds from the original model viewer

The four-byte records at runtime `$ECA2..$EE42` provide two endpoint pairs per
model ID. A negative start byte disables its span. The viewer clears the instance
selector at `$F0A0`; stepping at `$EF4C/$EFAA` moves toward an endpoint or switches
to the other enabled span. Zero selects the base model, while a positive selector
indexes the header's variant pointer table as `(selector-1)*4`. The Walker header
is aliased by IDs 0 and 1: ID 0 has zero endpoints, but ID 1 supplies its 22-frame
range. Ignoring that alias would incorrectly bound this table at zero.

Applying the original viewer's endpoint ranges gives 33 variant tables with
471 frame pointers. Every table ends exactly at the next declared model component
(the last ends at the next consumer's `$2ADF8` data address). Frame starts are
ordered without aliases; all frames within each model have the same length.
The nonnegative WORD offsets in its base vertex records enumerate consecutive
eight-byte records in each frame. Every XYZ triple is an even, in-pool encoded
coordinate reference. The frame blocks account for 36888 bytes and their tables
for 1884 bytes, precisely filling the previously excluded model-family gaps.

The rendering keeps frame data as WORD arrays with frame count/stride in the
owner role and symbolic frame pointer arrays. The pointer type describes only
the three-WORD coordinate-reference prefix; it does not invent the purpose of
the fourth WORD, turn a prefix into an aggregate pointee, or expand thousands of
identical record annotations unnecessarily. Other gameplay writers of the
instance selector are not exhaustively audited. These bounds establish a
conditional original viewer contract and original data extents, not a global
replacement-input or all-callers safety claim.

## Secondary object dispatch and shared names

At runtime `$8218`, the object loop reads a signed WORD from `$821C` indexed by
`2*object_type`, then jumps relative to the same base. The 148-entry literal table
ends exactly at already decoded code at `$8344`; its 24 distinct targets lie
outside the literals and inside the original image. Twenty-two were not accepted
code in the preceding analysis. Explicit original encoded entrypoints retain
their numeric symbols until their individual update roles are established.
These are dispatch entries with inherited loop/register/flag state, not independent
callable ABI contracts. The table interpretation requires the original type
domain 0..147; it does not validate arbitrary replacement object records.

The shared name table at `$F334..$F584` has 148 LONGs, not just the 104 model-viewer
entries. The remaining entries include placeholders and names used by object/UI
consumers. All original pointers refer to printable NUL-terminated text in
`$F584..$FD07`; repeated pointers and spare strings remain intact. The pool ends
before the adjacent non-text pointer/storage. Canonical character arrays keep
names readable without creating a separate annotation for every character/string.
The model viewer at `$F054` indexes this same table; other consumers include the
bounded inventory loops at `$1DC8/$349A6` and the indexed UI paths.

The other previously unresolved jump is at `$C6DE`. The diagnostic at `$C698`
prints the original RAM-corruption/reboot messages, waits for a key, loads A7
from address zero and its jump target from address four. That is an external
low-vector restart path, not a missing in-image function address. Its actual
vector value and platform-state validity remain unknown; no safe AmigaDOS exit
or observed runtime reboot is claimed.

## Projection scales

[Projection receipt](../../runtime/observations/starglider2-projection-scales.json):
three new interpretations name the lookup and its primary projection path and
put a compact arithmetic explanation in the rendered source. Every one of the
6252 original WORDs in `$2ADF8..$2DED0` was checked. With even byte offset `o`,
entry zero is `$7FFF`; offsets 2..128 equal `floor($4000/(o-1))`; offsets
130..12502 equal `floor($3FFF80/(o-2))`. The next WORD breaks that pattern.

The `$44AA` path uses lookup multiplication/doubling/SWAP after near-depth
clipping. Its large-depth alternative shifts XY by seven and uses signed DIVS.
The original coefficients and bias remain unchanged. The measured run is a
bounded data interpretation, not proof of the complete logical object extent,
all callers' bounds, or every small-offset use. No larger source range was
classified merely from adjacency.

A too-long header comment was refused atomically by the native 191-character
limit; shortening it used the existing guard, without framework changes.
Complete C and vasm reproduction remains exact. This adds 12504 classified bytes:
range ownership is 281265, code remains 89702 and the unclassified complement
is 131471. Media assets did not change, so the panel batch's separate native
