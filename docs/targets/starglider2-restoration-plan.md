# Starglider 2: original source restoration

Status: normal-media loader entries/bytes verified; first canonical source batch
rebuilds exactly with C and vasm. Semantic restoration remains in progress.
Scope: the UA/WOW Amiga disk already imported in this repository. Restore readable
original absolute-address assembly, extracted assets and exact raw payloads. No
relocation, C conversion or replacement OS loader is part of this project.

## Reproducible extraction

The private input is a 901120-byte ADF, SHA256
`77c633a9270f85361a30ba19175f5940155631ceb6c84b47b1efbb0bf2150ee3`.
Run `python -m amiga_reversing.tools.starglider2_extract input.adf --output PRIVATE_DIR`
with a fresh output directory. Do not publish the extracted copyrighted bytes.

| Disk span | Original destination | Entry / role |
|---|---|---|
| `$00000..$00400` | OS bootblock buffer; code copied to `$200` | Boot entry at source `$C` |
| `$02C00..$10600` | `$23FF8..$319F8` | Called at `$24000`; returning intro |
| `$16000..$7AE00` | `$1A000..$7EE00` | Second trackdisk read, 413184 bytes |
| `$16000..$7AC40` | `$1000..$65C40` after forward LONG copy | Main entry `$1000`, 412736 bytes |

The retained bootblock listing is
`targets/amiga_disk_starglider-2-1988-rainbird-cr-ua---wow/targets/amiga_raw_bootblock/bootblock.s`.
At source `$4C` it configures CMD_READ length `$DA00`, destination `$23FF8`,
disk offset `$2C00`, then calls `$24000`. The second setup at `$A0` reads
length `$64E00`, destination `$1A000`, offset `$16000`. At `$F0` the trap handler
loads source `$1A000`, destination `$1000`, count `$19310`; the loop at `$102`
copies one LONG per iteration, then jumps to `$1000`. The 448-byte read suffix
is not included in that copy; its purpose is not yet established.

The old `amiga_raw_bootloader_stage_1` descriptor assumes `$40000` and a `$5400`
span. That is not this bootblock's first transfer and must not be used as main
payload evidence. The corrected first-read source generated by the committed
backend has an entry saving registers, opening graphics.library, installing
display state and polling a button. Its exit restores registers and returns.
No main-game unpacking is established in this intro. Whether its low-memory
patches affect later game behavior remains an explicit runtime question.

Main-copy SHA256:
`662976920689c38fd47271ed7e656a92caf20aa20ce0b8801db2bdc77ba864d9`.
This is a raw loaded image, not an AmigaDOS executable. Static disk extraction
does not by itself qualify natural loader execution or every byte's role.

## Connected acceptance steps

1. Verify natural intro return and main entry against extracted bytes; follow any
   additional loads or self-modification actually encountered.
2. Import the recovered image through existing raw-target services. Resolve
   code/data ownership and structural refusals through canonical facts; never
   suppress a guard merely to emit a listing.
3. Restore connected functions, shared fields and table/asset consumers with
   evidence-backed names. Keep unresolved control/data explicitly unknown.
4. Generate canonical original assembly and INCBIN assets, verify complete raw
   payload equality with C and vasm, and package a standalone clean rebuild.
5. Deliver the copyrighted source/assets/raw output privately with README,
   provenance and checksums. Public commits contain only appropriate tooling,
   metadata and evidence descriptions. Do not promise a DOS HUNK or original
   disk reconstruction without separate demonstrated support.

## First source batch

The registered recovered target is `targets/amiga_raw_starglider2_game/`.
Its source descriptor, initial metadata and append-only Manual Action Log are
published; its `binary.bin` and generated listing remain private. To materialize
the target, copy the extractor's `game_copy.bin` to that `binary.bin`. The
original disk import remains registered separately, preserving its history.

The initial structural refusals at source `$3CD8E` and `$3E112` were inline
WORD dispatch tables. At `$3CD3E/$3CD42` and `$3E0C6/$3E0CA`, indexed PC loads
and LEAs select offsets consumed by the jumps at `$3CD8C/$3E110`. Both tables
occupy 32 bytes; the second selector is explicitly masked with 15. This does
not establish validity of arbitrary first-table indices or every record producer.
Canonical layouts plus required data seeds prevent treating the tables as code.

Five code labels and three further layouts name the entry/initialization path,
workspace clearing loop, platform runtime setup, drawing lookup initialization,
platform/entry flags, workspace-base pointer and 200 WORD raster-row offsets.
The Amiga initializer fills the latter with `0,40,...7960`; indexed renderer
consumers use doubled row indices. Flag bit15 selects the Amiga path; bit0
controls fixed workspace setup and whether SuperState is called. Other flag bits
and general startup-environment contracts remain unassessed.

Two renderer defects were exposed and fixed without changing game bytes:
planned access evidence truncated long CIA mask expressions; numeric absolute-W
addresses in the upper signed half needed explicit sign extension for vasm.
The small synthetic regressions and catalogue/extraction suite pass 77 tests.

[Normal-media entry receipt](../../runtime/observations/starglider2-loader-entry.json)
records an unchanged ADF cold boot on A500 OCS/68000, 512K Chip + 512K Slow RAM.
All 55808 intro bytes matched at PC `$24000`. A normal port-one blue-button
hold released the intro, and all 412736 game bytes matched at PC `$1000`; the
button was released there. No memory/register injection or direct-payload loader
was used. This qualifies extraction, not gameplay, graphics/audio equivalence,
or the later effects of the intro's low-memory patches.

The [first source receipt](../../runtime/observations/starglider2-initial-source.json)
binds native/vasm builds to the canonical actions and original payload. Both
assemblers reproduce all bytes. This baseline is not a readable-restoration
completion: much data and many function/field roles remain unclassified or
anonymous, no assets are yet independently typed for INCBIN export, and there
is no semantic completion percentage. Next: restore the connected drawing-mask
tables and their initializer/consumers, then choose the next evidence-backed
subsystem from the native gap inventory.

## Drawing masks and first Paula assets

Four constant tables at runtime `$3DDAE`, `$3DE2E`, `$3DEAE`, `$3DECE`
contain 32 LONG prefix masks, 32 LONG suffix masks, 16 WORD prefix masks and
16 WORD suffix masks. Every value was checked: prefix `all_bits ^
(all_bits >> index)`, suffix `(1 << (bits-1-index))-1`. Startup at `$3E96E`
combines the prefix at the smaller index with the suffix at the larger index.
The Amiga arm writes all 32x32 LONG entries at `$3FFBA` and all 16x16 WORD
entries at `$40FBA`; the alternate platform arm writes only the first 1024 bytes
of the former. Original seed bytes remain preserved, not promoted into meaningful
precomputed values. The 200 row-offset WORDs and the four constants now have
array elements, not merely owner labels.

The routine at `$4DEDC`, now `initialize_paula_sample_channels`, configures four
channels and enables audio DMA. Three retained sample spans are fixed directly
by its address arithmetic and AUDxLEN WORD counts:

| Runtime data span | Length | Native private INCBIN |
|---|---:|---|
| `$59F34..$5E204` | 17104 | `paula_initial_channel0_sample.bin` |
| `$5E220..$5E5D4` | 948 | `paula_initial_channel1_sample.bin` |
| `$5E5F0..$60A14` | 9252 | `paula_initial_channel2_sample.bin` |

Channel 0 starts at volume 24; channels 1 and 2 start at volume zero. This is
source-backed Paula data classification, not identification of the audible
effects, playback reachability, or an audio-output comparison. Their preceding
record headers, inter-record gaps and fourth channel's zero-filled buffer have
not been included in these asset spans. None has a current native code-entry
reference; this alone is not proof that no indirect caller can ever reach them.

The native binary-assets source package has three assets (27304 bytes) and
rebuilds all 412736 original bytes with vasm; the inline source independently
rebuilds with C. A small projection correction keeps descriptive layout roles
as comments instead of invalid native subtype names, preserving explicit media
types. The focused suite passes 81 tests. The append-only catalogue contains
36 actions, without claiming Decision Journal semantic acceptance.

Across the initial/raw analysis and these source batches, the union of native
range ownership grows from 101084 to 129142 bytes; the complement within the
412736-byte payload falls from 311652 to 283594. Overlapping ownership is counted
once. These are classification counts, not purpose or semantic completeness.
See [drawing/audio source receipt](../../runtime/observations/starglider2-drawing-audio-source.json).

## Recovered span dispatches

Native tracing had incorrectly treated the base of `LEA d8(PC,Dn),An` as a
complete address, dropping the index. Small fixtures reproduced both a false
target for an unknown index and a wrong target for a known nonzero index. The
fix retains numeric indices with proper WORD sign extension and transports the
existing WORD-relative-table value into a PC-indexed LEA. Unknown, clobbered,
unsupported and address-domain-only values do not become numeric indices.
Table scanning/enqueueing also stops before a following zero becomes a bogus
handler at the already-consumed table data. This is scoped recovery, not a full
effective-address evaluator or arbitrary-input jump-table proof.

The two jumps at source `$3CD8C` and `$3E110` now each identify the actual 16
table handlers. Both WORD tables render symbolic target-minus-base expressions.
All 16 planar handlers have color-specific labels: their partial-span writes
OR the inside mask into precisely the planes selected by the four color bits,
AND the outside mask into the others, at plane strides `$2000`. They are handler
entry labels, **not independently callable function contracts**: their initial
BPL uses the flags established before dispatch. The interleaved dispatcher is
named separately; its handler color meanings are not promoted by analogy.

This recovers 6582 additional code bytes (88142 total native code bytes), with
some previously inferred data reclassified as code. The union-based unclassified
complement falls by 3110 to 280484 bytes, not by the entire code increase. Both
assemblers again reproduce all 412736 bytes. Twenty evidence-bearing naming and
reference interpretations are accepted through the normal Decision Journal,
bound to a current exact rebuild receipt; the older 36 ordinary catalogue
actions remain unassessed there.

The focused suite passes 93 tests. Three selected existing native regressions
pass; `test_project_source_facts_v2_pc_indexed_absolute_long_dispatch_table_roundtrips`
has a pre-existing exact-line-format assertion failure, independently reproduced
with the unmodified analyzer. It has not been changed or counted as passing.
See [span-dispatch receipt](../../runtime/observations/starglider2-span-dispatch.json).
