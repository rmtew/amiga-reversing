# Animation node selection and frame sequences

This slice continues from `0d1af99b`, using the shared schema and pointer-exception
workflow for further Pandora restoration. It makes script-selected nodes and
frame sequences symbolic through existing canonical types and bounds.

## Semantics and scope

Six accepted behavior handlers read command+2 as an animation node, install it
in the selected position state, reset its index/phase and clear held-header mode.
Three also copy command+6 into node+6. The animation updater reads node+6 as a
LONG pointer-entry sequence: entry zero supplies the held pose, and entries at
`4 + index*4` supply animated geometry. The frame count and phase clock remain
separate fields. Chained nodes can use an extension at node+$12 beyond the basic
18-byte prefix; this slice does not flatten that variant or claim all dynamic
writers are understood.

Four field rules promote 219 already-bound scalars: 82 short-command node
pointers, 26 long-command node pointers, 26 long-command sequence pointers and
85 node sequence pointers. All original values are nonzero. The required split
at `$49F6A` remains an unresolved pointer boundary, alongside the older `$49030`
and `$49134` fragments. No boundary was removed to obtain a symbolic result.

Native resolved coordinates select 39 unbound stride-four array owners. One
additional established icelord array is independently qualified despite its
split referring field: its held header points to the last accepted frame and
its following 19 entries enumerate the existing 19-frame owner. These 40 arrays
reuse `WorldPositionDescriptorPointer`, whose single field points to
`WorldPositionAnimationFrame`. They add 329 typed entries, including two NULLs;
no new type, layout bounds or per-entry aliases are invented. Across the 44
referenced owners, including four already typed, all 395 nonzero entries match
accepted frame starts and three entries are NULL.

All 84 complete original node references have enough remaining physical slots
for their held header and declared frame count. All 26 script replacement pairs
also fit using their original node counts. Those checks do not establish later
mutations, execution ordering, reachability, chained-node extent or RAM lifetime.

## General framework gap found and fixed

The first full reassembly caught a mapped pointer referencing an autogenerated
array-field name that was suppressed by source rendering. Requiring the same
label-emission predicate removed that invalid expression; the exception report
then exposed 53 references without a usable native containing owner.

Canonical binding projection now carries the exact source label-owner extent
on its first named leaf. This optional pair comes from the existing element
binding, is omitted for legacy entities and does not widen the leaf's rendered
data range. Native resolution requires a valid enclosing span within the decoded
section, an actually emitted label and exact encoded logical-value equality.
It prefers an emitted explicit name, otherwise uses the containing owner plus
byte offset. Missing, malformed or out-of-section spans stay explicit exceptions.
There is no overlapping wide data item, nearest-label guess, game-specific base
subtraction or second mapping store.
