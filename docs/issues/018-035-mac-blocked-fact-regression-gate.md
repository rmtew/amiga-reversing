Status: active

## Proposal Context

- Source proposal: `docs/proposals/018-platform-executable-format-knowledge.md`
- Blocked by: `docs/issues/018-030-executable-kb-restart-and-state-sync.md`
- Stronger after: `docs/issues/018-034-parser-fact-coverage-report.md` and
  `docs/issues/018-037-macos-blocker-resolution-or-final-deferral.md`
- Purpose: ensure Mac byte-entry and relocation/fixup facts remain blocked or
  deferred until real accepted evidence exists.

## Knowledge Delta

No new accepted Mac facts are expected. This issue should strengthen the
negative evidence boundary:

- `movea.l (a7)+,a0` may remain candidate evidence only;
- nonzero CODE byte-entry rules must not be accepted without citation or
  parser assertion;
- classic 68K CODE relocation/fixup parsing must remain deferred without exact
  record location, encoding, affected offsets, and application rules;
- web/artifact/listing output must label these states as candidate/deferred.

## Default Behavior

Current Mac views should remain available. The gate must prevent status
promotion, not remove candidate visibility.

## Evidence Standard

Tests must prove consumers cannot treat candidate byte-entry or deferred
relocation/fixup state as accepted parser authority.

## Implementation Slice

AFK slice:

- audit current Mac parser/listing/project/artifact/web paths for byte-entry and
  relocation status text/fact ids;
- add regression tests for blocked/deferred state at the strongest current
  surfaces;
- update validator/report output if needed so failures are obvious;
- update Proposal 018 and/or Proposal 012 with any remaining gap found.

## Research Completion Standard

Complete only after a first-pass path audit and a second-pass negative-safety
review. Do not close by claiming accepted evidence; close by proving the block
is enforced.
