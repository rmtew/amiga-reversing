# Migrate Disassembler View To Canonical Forms

Status: Ready for agent
Parent PRD or proposal: `docs/prd/024-m68k-canonical-form-model.md`
Type: AFK
Blocked by: None

## Scope

Make decoder/disassembler metadata a generated tool view over canonical form ids.

## Out of scope

- Renderer polish unrelated to canonical identity.
- Simulator/effect migration.

## Files likely touched

- `src/scripts/`
- `src/generated/m68k_disassembler_tables.*`
- `src/m68k_disassembler.c`
- `tests/`

## Acceptance criteria

- [ ] Decode candidates are canonical form ids.
- [ ] Decode buckets are generated from canonical forms.
- [ ] Candidate order is generated by specificity.
- [ ] Equal-specificity ambiguity fails generation or strict coverage.
- [ ] Disassembly results no longer repair private disassembler identity back to assembler identity.

## Required tests

- [ ] Test representative opcode decode returns expected canonical form id.
- [ ] Test generated ambiguity rejection with synthetic or fixture data.
- [ ] Test decode/render behavior remains correct for existing disassembler tests.

## Cleanup / deletion

- Delete disassembler-only form identity and runtime joins to assembler forms.

## Notes for agents

Runtime can validate candidates, but ambiguity policy belongs upstream.
